# Flagship Build Spec — LOCKED & APPROVED

**Status:** Approved by Dotun. This file is the build's source of truth. Full detail (architecture, data flow, risk register, citations) lives in `flagship_final_plan.md`. Where the two differ, THIS file wins, because it carries the owner's final adjustments.

## Product, one line
A multi-tenant embeddable AI support assistant. An owner feeds it their content (PDFs including scanned/image PDFs, plus a small site crawl), drops one script tag on their site, and the widget answers visitors grounded only in that owner's content, refuses with an honesty verdict when it cannot ground an answer, and resists prompt injection. The reliability/evaluation layer is the product.

## Owner adjustments that OVERRIDE the final plan
1. **Demo is private.** Deploy to a hosted URL, share to a recruiter on request. Do NOT promote a public front door. The public narrative stays build-in-public: the messy process, the failing evals, the red CI, the fixes.
2. **LLM budget = Gemini via Vertex AI free credits ONLY.** Generation, vision (image PDFs), and embeddings all run on Vertex/Gemini. The multi-provider abstraction is still built (engineering signal + a real fallback seam), but Gemini is the live model and we state that plainly. The CI gate is a three-lane gate (locked 2026-07-02, correcting an earlier false claim that the DAG metric is rule-based with no paid judge; it is actually LLM-judged and defaults to a paid OpenAI model unless a Gemini judge is set): Lane 1 is plain no-LLM checks (typed-output assertions plus DeepEval Tool Correctness) and is the reproducible core that can never flap; Lane 2 is the DAG faithfulness metric with the judge explicitly pinned to Gemini, temperature 0 plus seed, result caching, and a measured threshold margin; Lane 3 is warn-only judged metrics that never block. Any LLM-judge metric uses Gemini, with same-family bias documented honestly and cross-family flagged as the production upgrade. Show cost discipline: prompt caching, content-hash dedupe before any vision call, embedding cache, gated OCR. Cost and latency are handled, not the centerpiece. **Cost posture:** the only credit card needed anywhere is the Google Cloud billing card that activates the Vertex free-trial credit, and that credit is spent only on Gemini API calls. Hosting (Render/Fly free + keep-alive ping) and every other service (Supabase, Sentry, Logfire, GitHub, Weaviate self-host via Docker) stay free and card-free.
3. **UI is minimal.** The dashboard is product-only: upload, status, results, trace link. Red→green is shown via the real GitHub Actions CI run plus the build-in-public posts, NOT a custom eval-visualization UI.

## Locked stack
- Agent: PydanticAI on Python/FastAPI (one service: API + agent + ingestion worker)
- LLM + vision + embeddings: Gemini via the **Vertex AI API** (free credits). Vertex is used ONLY as the Gemini API, never for hosting, so hosting compute does not consume the Gemini credits.
- Vectors: Weaviate (multi-tenancy enabled, two tenants, hybrid search)
- Relational + auth: Supabase / Postgres (RLS forced)
- Eval: DeepEval three-lane CI gate (Lane 1 no-LLM assertions + Tool Correctness = reproducible core; Lane 2 DAG faithfulness metric with a pinned Gemini judge and a measured margin; Lane 3 warn-only judged metrics) + one agentic metric; online referenceless scorer on sampled traces
- Observability: Logfire (OpenTelemetry). Errors: Sentry
- MCP: remote Streamable-HTTP server acting as an OAuth 2.1 Resource Server, Origin-validated, verifies an **external-caller token** (an OAuth token or scoped API key that carries the tenant), **NOT the owner Supabase login JWT**. Validates signature/issuer/audience/expiry, rejects tokens not issued for this server, no token passthrough upstream. Scoped: full OAuth (dynamic client registration, PKCE, Protected Resource Metadata per RFC 9728) written up, audience/issuer validation demonstrated live. Day-1 issuer for the demonstrated check is a self-minted scoped API key (free, in our control); the delegated-authorization-server path is the documented production upgrade.
- Dashboard: React + Vite (minimal). Widget: Lit + Shadow DOM + Vite library bundle, served from a CDN
- Object storage: R2 or Supabase Storage (presigned PUT for large uploads)
- Hosting: the Python service runs on a **free tier (Render free, or Fly)**, kept warm with a **free keep-alive ping** (UptimeRobot, cron-job.org, or a GitHub Actions cron hitting `/health` every ~10-12 min, under Render's 15-min idle sleep). **NOT hosted on Google Cloud**, so hosting never draws down the Vertex/Gemini credits. Cold starts are small anyway because models are remote (Vertex API), not local weights in the container.
- CI: GitHub Actions (runs tests + the eval gate)

## Locked decisions
Single-tenant-excellent (two tenants + a passing isolation test, scale path documented); one Python service; **three request paths across two trust domains, each resolving tenant from its own credential** (owner Supabase JWT for login/ingestion; public widget-key + Origin allowlist for visitors, no login; external-caller token for the MCP); the **visitor edge gate** (widget-key + Origin allowlist + rate limit + sanitize) lives as **FastAPI middleware**, with a thin Cloudflare Worker + WAF rate-limiting front documented as the production move and an optional Day-11-buffer stretch (not load-bearing; do not hand-roll rate limits in KV); scoped MCP with external-caller token auth; **core capabilities as plain functions exposed two ways via thin adapters** (in-process for the widget, MCP tool for external callers); **honesty verdict fused into the answer capability** (never an optional tool); dev-docs seed corpus; Logfire for online eval; three-lane eval gate (no-LLM core + Gemini-judged DAG lane + warn-only lane); self-render vision for image pages.

**Decisions (2026-07-02):** (1) Eval gate locked to the three-lane design above. Open task before Day 7: define what makes a response good vs bad (the answer-quality criteria), because that determines what Lane 1's no-LLM checks can enforce versus what Lane 2's Gemini judge must handle. (2) Website crawl deferred: for the 12-day build, ingestion is uploaded PDFs only; the crawl/read-a-website lane is a later addition, with public seed data sources to be researched when it is picked up. (3) Postgres is the durable source of truth for ingested content, not just document/job status. Ingestion stores each document's extracted chunks in Postgres (chunk text plus metadata: document id, section/position, content hash) AND each chunk's embedding vector, per tenant with RLS forced. Weaviate holds only the search index, derived from those Postgres rows. If Weaviate is ever lost, a reindex job rebuilds it from Postgres with no customer re-upload, and because the vectors are stored too, with no re-embedding cost. This also lets the dashboard read document structure and status straight from Postgres. Impact: adds a tenant-scoped `chunks` table (RLS forced, auto-covered by the Day-2 isolation sweep); the real chunks and vectors are populated by ingestion (Days 3 to 5); Weaviate becomes a rebuildable derived index, not a source of truth. Seed corpus confirmed: developer docs, with seeded data in Supabase acceptable.

**Key storage:** widget keys are public identifiers stored in Postgres, each linked to its tenant and its allowed origins (not hashed; their safety is origin-binding + rate limit + narrow scope). The MCP external-caller credential is a self-signed token verified by a signing secret in the env on Day 1; it moves to a hashed-keys table in Postgres (key hashed, linked to tenant + scope + expiry) when multiple AI clients exist.

## Build sequence (12 working days, riskiest spikes first)
- **Day 1** — Auth spine on the primed scaffold + MCP spike (repo/CI already done in Milestone 0). Three request paths across two trust domains, each resolving tenant from its own credential: (a) owner Supabase JWT verify, the only real login, gates ingestion; (b) visitor widget-key gate as a first-class piece (key store + Origin/Referer allowlist + sanitize-to-query; rate limit stubbed behind a clean interface, real on Day 11); (c) MCP spike: remote Streamable-HTTP Resource Server validating an external-caller token (sig/iss/aud/exp) + Origin 403 + no token passthrough. Core capabilities as plain functions (retrieve, answer-with-verdict) behind two thin adapters (in-process for the widget, MCP tool for external callers); core stubbed (real on Days 5-6). BFF secret guard + test. If the day runs long, the safe cut is to stub the rate limiter and ship only the MCP audience/issuer check live.
- **Day 2** — Tenant isolation, proven: RLS forced + Weaviate two tenants + a test that tenant A cannot read/write tenant B. **(non-negotiable)**
- **Day 3** — OCR/vision PDF spike: native text → gated OCR → Gemini-vision for image pages; poison PDFs parsed in a subprocess → DLQ. **(non-negotiable)**
- **Day 4** — Ingestion end-to-end (presigned upload, queue, idempotent upsert, status, DLQ, backpressure).
- **Day 5** — Agent + grounded answer (PydanticAI, tenant-scoped hybrid retrieval, Gemini behind the interface, typed verdict).
- **Day 6** — Refusal + prompt-injection guardrail (honest refusal; pre-screen + spotlighting; blocks "ignore previous instructions").
- **Day 7** — Observability + the non-flapping eval gate (Logfire, Sentry, DeepEval golden set, DAG gate in CI).
- **Day 8** — Red→green (push bad change → CI red → fix → green, reproducibly) + agentic metric + online scorer. **(non-negotiable: reproducible red→green)**
- **Day 9** — Minimal dashboard + deploy to a hosted URL, seed two tenants (dev docs), kept private/shareable. **(non-negotiable: deployed and reachable)**
- **Day 10** — Embeddable Lit/Shadow-DOM widget (isolated, fetch-streaming, CDN bundle, works on three host pages without breaking them).
- **Day 11** — Injection demo on the live URL (refuse + resist) + adversarial block-rate + widget telemetry + flow polish.
- **Day 12** — Hardening + README essay with the week's real numbers + MCP OAuth and scale-seam write-ups + architecture diagram + a 60-90s clip.

**Spine to protect:** Day-2 isolation test, Day-3 poison-PDF survival, Day-8 reproducible red→green, Day-9 deployed. If a day slips, Day-11 telemetry is the buffer.
